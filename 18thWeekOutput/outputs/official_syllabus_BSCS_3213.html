Course Syllabus: BSCS 3213
I. Course Identification & Specification
Course Code BSCS 3213 Course Title Software Engineering
Credit Units 3 Units (Lecture: 2 hrs/wk, Lab: 3 hrs/wk) Prerequisites CS 3110 (Data Structures and Algorithms)
Course Description Systematic engineering methodologies for software development, covering SDLC models, Agile/Scrum frameworks, requirements engineering, object-oriented analysis and design with UML, architectural patterns, unit and integration testing, continuous integration and deployment (CI/CD), and software project management.
II. Course Learning Outcomes (CLOs)
CLO ID Outcome Statement (Measurable Bloom's Verb) Cognitive Level Mapped POs
CLO1 Design software solutions using appropriate SDLC models and Agile frameworks. Create PLO2, PLO5
CLO2 Analyze requirements and design system architecture using UML diagrams. Analyze PLO2, PLO3
CLO3 Implement unit testing and CI/CD pipelines to ensure quality standards. Apply PLO2, PLO5
CLO4 Evaluate project performance and communicate technical progress to stakeholders. Evaluate PLO3, PLO5
III. 18-Week Semester Instructional Matrix
Wk Topics Covered Lesson Learning Outcomes (LLOs) TLAs & Exercises Assessment & Evidence
1 Introduction to Software Engineering, History and Evolution of SE
  • K Define the scope and objectives of software engineering projects.
  • S Identify key stakeholders in a software development lifecycle.
  • A Appreciate the ethical implications of software design.
  • Lecture on SE History
  • Group Discussion
  • Participation Rubric
2 Software Development Life Cycle (SDLC), Waterfall vs. Agile Models
  • K Select appropriate SDLC models for specific project contexts.
  • S Map project phases to Agile or Waterfall frameworks.
  • A Value iterative development over rigid planning.
  • Case Study Analysis
  • Model Comparison Workshop
  • Quiz on SDLC Models
3 Requirements Engineering, Functional and Non-Functional Requirements
  • K Analyze user needs to formulate system requirements.
  • S Draft functional specifications using use case diagrams.
  • A Demonstrate empathy for end-user constraints.
  • Requirement Gathering Simulation
  • Peer Review
  • Requirements Specification Draft
4 Unified Modeling Language (UML), Use Case and Sequence Diagrams
  • K Analyze system interactions using UML notation.
  • S Construct sequence diagrams for business logic flows.
  • A Adhere to standard UML documentation conventions.
  • UML Diagramming Lab
  • Diagram Critique
  • Diagram Accuracy Check
5 System Design Patterns, Architectural Styles
  • K Design scalable system architectures using standard patterns.
  • S Implement modular components within a monolithic structure.
  • A Prioritize maintainability and scalability in design.
  • Pattern Matching Exercise
  • Architecture Workshop
  • Design Pattern Application
6 Agile Methodologies, Scrum Framework Implementation
  • K Create sprint plans based on backlog prioritization.
  • S Facilitate daily stand-ups and sprint retrospectives.
  • A Embrace adaptability in changing requirements.
  • Role Play Scrum Master
  • Backlog Planning
  • Sprint Plan Evaluation
7 Software Testing Fundamentals, Unit Testing Strategies
  • K Implement unit tests to validate individual components.
  • S Write automated test cases for critical functions.
  • A Commit to quality assurance standards.
  • Test Case Writing Lab
  • Code Review
  • Unit Test Coverage Report
8 Continuous Integration and Deployment (CI/CD), Pipeline Configuration
  • K Configure CI/CD pipelines for automated builds.
  • S Implement automated deployment strategies using scripts.
  • A Value transparency in development processes.
  • Pipeline Setup Lab
  • Automation Workshop
  • Pipeline Execution Log
9 Midterm Examination, Review of Weeks 1-8
  • K Evaluate understanding of SDLC and UML concepts.
  • S Demonstrate proficiency in design and testing skills.
  • A Reflect on academic progress and learning gaps.
  • Midterm Examination
  • Formative Assessment Rubric
10 Integration Testing, System Testing Strategies
  • K Analyze system interactions during integration phases.
  • S Execute integration tests to verify component compatibility.
  • A Demonstrate patience during debugging processes.
  • Integration Test Lab
  • Bug Tracking
  • Test Execution Report
11 Performance Testing, Load and Stress Analysis
  • K Evaluate system performance under load conditions.
  • S Formulate optimization strategies based on metrics.
  • A Appreciate the impact of performance on users.
  • Performance Benchmarking
  • Metric Analysis
  • Performance Test Results
12 Quality Assurance (QA), Defect Management
  • K Implement QA processes to ensure quality standards.
  • S Manage defects using tracking systems effectively.
  • A Commit to continuous improvement in quality.
  • QA Process Simulation
  • Defect Triage
  • Quality Audit Report
13 Project Performance Evaluation, KPIs and Metrics
  • K Evaluate project performance using key performance indicators.
  • S Calculate and interpret project metrics accurately.
  • A Demonstrate accountability for project outcomes.
  • KPI Calculation Workshop
  • Data Analysis
  • Performance Evaluation Form
14 Stakeholder Communication, Technical Reporting
  • K Communicate technical progress to non-technical stakeholders.
  • S Prepare clear and concise project status reports.
  • A Show respect for diverse stakeholder perspectives.
  • Report Writing Lab
  • Presentation Practice
  • Status Report Review
15 Risk Management, Project Risk Assessment
  • K Identify potential risks in software projects.
  • S Formulate mitigation strategies for identified risks.
  • A Demonstrate proactive attitude towards risk management.
  • Risk Assessment Workshop
  • Scenario Planning
  • Risk Register Draft
16 Capstone Project Development, Final System Design
  • K Design final capstone system architecture.
  • S Implement core features of the capstone project.
  • A Collaborate effectively in team environments.
  • Capstone Development Lab
  • Team Collaboration
  • Progress Checkpoint
17 System Integration, Final Testing and Debugging
  • K Integrate all components of the capstone system.
  • S Execute final testing and resolve critical bugs.
  • A Demonstrate diligence in final quality assurance.
  • Final Integration Lab
  • Bug Fixing Session
  • System Readiness Report
18 Final Examination & Capstone Defense, Course Review
  • K Evaluate comprehensive knowledge of software engineering.
  • S Defend capstone project before the board.
  • A Reflect on overall course learning and growth.
  • Capstone Defense
  • Final Exam
  • Final Examination & Rubric
